# B1 组合运行时安装预检

本候选把固定的 B0（公开确定性恢复基线）、B1（模型单智能体）只读运行时与长期会话组件放入同一镜像，仅验证安装、依赖和离线导入。它不启动原题、恢复控制器、模型推理或完整 AIOS（智能体操作系统）服务。

来源为 B0 `22fa7c1`、已通过真实模型只读门的 B1 `43b15ea`、已通过 30 项受控会话契约的 `5008fe9`。原 B0 包的清单列出 60 个文件，其中 37 个属于公共运行负载；原 B1 派生包的清单列出 264 个文件，其中 254 个属于运行负载。上述清单计数不包含各清单文件自身。新的构建上下文仅包含允许安装的公共内容和固定模型文件。

原 B0 负载只保留已审的单体角色派生，原入口和恢复策略保持。其 `--preflight` 参数只在本次独立预检容器的空 `/logs` 中执行一次，保留数据库写入排他、唯一收据与原生依赖检查。AIOS 原导入预检、两个解释器及 SQLite（嵌入式数据库）的实际身份、llama.cpp（本地模型推理运行时）的动态库加载、固定模型字节摘要分别核验。模型文件校验不代表推理已执行。

容器使用对应宿主的非特权用户和组；结果目录保持仅所有者可访问的 `0700` 权限。运行期间无网络、根文件系统只读、能力全部丢弃，只有专用结果目录可写入宿主。构建和下载阶段的联网行为单独记录。

主结果为 `COMPOSITION_PREFLIGHT_RESULT.json`。工作流保存全部命令原输出、来源绑定、实际身份、受限资源清理及归档摘要。失败场同样导出，旧场不会被覆盖。总工作流最长 48 分钟；这些是安装预检的资源界限，不改变任何原题比较预算或事故时钟。

通过本门仍不能宣称完整 AIOS 会话接入、模型逐动作决策、完整低层工具平等、原题成功或多智能体加速。正在运行的 B0 原题实验独立保持冻结。

## 第二场的窄修

首场 `44517427524` 已完整保留：18 项安装检查中 17 项通过，原 AIOS 导入因数字用户没有可解析的主目录而失败。新候选在已有 `/tmp` 内存文件系统中为隔离用户创建 `0700` 私有主目录，只向受控子进程提供标准主目录环境；两套解释器实际核对解析结果、所有者和权限。外层宿主与父进程环境不变，原组件、镜像构建配方、原十条子命令与预算均保持。

另外修正一处证据记录字段的变量遮蔽：宿主预期安装清单摘要在第一场已经实际比较，但结果字段后来误记为会话源码字典。新候选独立保留该摘要变量；第一场原始记录不回填、不覆盖。
