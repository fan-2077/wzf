# 单智能体公共恢复辅助会话

本候选处理一个具体的接入问题：完整恢复可能长于单次 SDK（软件开发工具包）工具请求的等待上限。客户端需要启动一次长期辅助任务，并持续查询同一任务；查询断连不能成为再次执行恢复的理由。

## 当前范围

此目录是独立的源代码候选，基础提交为 `22fa7c12ea5274f86a2ecca17e6cc2e16ab7a4ad`。原 `b0-run` 和 `g1-smoke` 目录保持原字节。固定原题仍为 `gitlab_notification_intermittent_replicated`，原框架提交仍为 `148dded7ca2737ded1085e7dc7bbf2a8fcfe7861`。

候选接入完整公共 B0（确定性恢复基线）辅助。它保留原动作账本、准入条件、业务动作、异常收束和唯一原题提交。单智能体角色由可信宿主绑定；模型不能在请求中选择身份、目标、预算、工作目录或任意命令。

本目录尚未建立完整强 B1（模型驱动的单智能体恢复基线）。较低层动作工具、完整证据进入模型的策略、组合镜像、模型调用预算及实际远端资格必须分别完成。已通过的三轮模型只读接入，为后续组合提供了依据，并不等于本候选已经完成真实恢复。

## 必须保持的执行语义

1. 每场只有一个会话所有者和一个完整恢复辅助。所有动作使用同一物理实例、同一公共账本及同一事故时钟。
2. 启动意图先持久记录，之后才创建辅助进程。记录为已预留启动后，所有者崩溃、返回丢失或超时均不能自动创建第二个辅助。
3. 客户端在启动前取得固定辅助标识。请求和响应保留原始字节；相同请求编号与相同内容可查询原记录，编号复用但内容不同必须拒绝。
4. 查询只读取已有任务的状态及已允许的公开结果，不构造新的 `Controller`（恢复控制器）或 `Driver`（公共动作驱动），不刷新预算、不退还已消耗或未知的额度。
5. 原框架的启动上下文、隔离边界证明、构建记录、实际源码摘要、资源记录和异常结果收束全部保留。生成的公共辅助只对可信角色作显式覆盖，实际加载目录须与派生清单匹配。
6. 进程状态、公共业务观察、原题提交状态和原始评估结果分别保存。进程以退出码零结束，并不单独证明原题通过。
7. 辅助内部所有动作与原生调用都应计入原公共预算。一个外层工具调用不能把完整恢复的内部成本隐藏成一次廉价操作。

## 与公平比较的关系

后续强单智能体、多智能体串行与多智能体并行对照，都应拥有相同的完整合法辅助集合。如果采用逐动作调度消融，关闭完整辅助的条件必须对各组一致。

同一固定实例若可由公开确定性程序完成，就应承认它能够集中式求解。增加角色数量、工具请求重叠或成功解析一份结果文件，都不能替代原题成绩和完整时钟上的实测比较。

## 来源与验证边界

`BASE_BINDING.json` 记录固定来源与已通过的 B1 只读接入证据。`CANDIDATE_SCOPE.json` 记录本候选的完成范围。接口由 `CONTRACT.json` 定义；实现完成后才记录本地验证结果和独立审查结论。

本地故障检查可以验证进程、文件、真实 SQLite（嵌入式数据库）事务、请求身份和拒绝重复启动的语义。它不能替代固定隔离镜像内的原生调用、AIOS（智能体操作系统）组合、完整业务恢复或四路并发执行的实际证据。

## 固定运行时契约门

专用工作流 `sre-b1-session-contract-uid-v2-20261119.yml` 只在同名隔离分支运行。它使用原 B0 镜像构建定义，验证 Python 3.11.17、SQLite 3.54.1 及固定数据库源码身份，然后在无外部网络的容器中执行本目录测试。原题部署、模型启动和真实恢复均不在此工作流中。

测试容器只读挂载两份源目录，仅向专属结果目录写入记录；处理器上限为 4 核，内存上限为 8 GiB（每 GiB 为 2 的 30 次方字节）。镜像、容器及挂载来源的实际身份会另行核验，清理仅针对本场已绑定的资源。

`B1_REQUIRE_REAL_IPC=1` 要求真实 IPC（进程间通信）测试必须执行。固定运行时不匹配、通信能力缺失、测试失败或任何跳过项，都会使契约门失败。本地环境若因 `EPERM`（权限不允许）跳过真实套接字测试，只能报告“尚未验证”；连接替身测试不能代替这一门禁。

工作流分别保存测试结果、前后源码摘要、原始命令日志、构建记录、实际容器配置、清理结果和完整归档。归档成功与契约通过是两个状态；两者都不代表完整强 B1 或原题恢复成功。
