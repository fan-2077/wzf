# 第十轮实验计划与停止条件

本轮从第九轮证据继续，目标是把联合动作从4辆车的16种组合扩展为8辆车的256种组合，仍使用同一固定公开车流与同一动态信号事件。

这轮只做确定性仿真和基线能力边界检查，不运行语言模型，不声称多智能体收益。独立子智能体启动接口在当前会话不可用；不会把并行计算进程或多个提示上下文冒充独立研究代理。

## 预先冻结的规则

- 固定 CityFlow 与 CoLLMLight 提交。
- 固定杭州4×4路网和固定车流文件散列。
- 仿真时刻705前，根据车辆ID排序、当前道路去重、车道可行替代路线、未来受影响移动，选择前8辆车。
- 不足8辆即停止，不降低目标、不事后挑选。
- 故障位置、相位、持续时间、仿真窗口和队列约束与第九轮一致。
- 运行全部256种等待/改道组合，每种使用独立新仿真实例。
- 每个动作都要验证原生路线回读、实际访问道路、目的地到达、故障相位读数和全网队列。
- 以全等待为队列上限参照，最多增加5%；该值只是实验约束，不是现实交通安全标准。

## 解释边界

256种组合仍然可以确定性穷举，所以本轮不可能证明多智能体必要。它只能回答：
1. 8车下局部最优动作组合是否仍会输给全等待？
2. 是否存在全局联合动作优于全等待？
3. 穷举256个完整仿真需要多少真实墙钟时间和资源？
4. 是否有资格进入更大规模或多个事件的研究？

固定车流不是随机需求生成器，修改 seed 不能当作独立交通需求泛化。若8车结果支持继续，下一轮应改变真实需求文件、事件位置或路网，并建立更强的确定性优化基线。
